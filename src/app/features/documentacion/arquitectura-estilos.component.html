Arquitectura de estilos

Guía para entender cómo está montado el diseño del proyecto: qué hace cada carpeta, qué es un token, cómo conviven PrimeNG y Tailwind, y cómo hacer cambios comunes (como cambiar un color) sin romper nada. Escrita para que la entienda cualquiera, sepa o no de CSS.

1. Visión general

El diseño se apoya en tres herramientas que se reparten el trabajo, más una "fuente única de verdad" que las conecta:

PrimeNG

Librería de componentes listos: tablas, selects, calendarios, botones, drawer… Trae el comportamiento y la estructura complejos ya resueltos.

Tailwind CSS

"Clases utilitarias" para armar el layout: separación, columnas, alineación, tamaños. Se escriben directo en el HTML.

Tokens + SCSS

Nuestras variables de diseño (colores, tamaños, sombras) y los patrones reutilizables (tarjetas, campos, badges).

Analogía: piensa en una casa. PrimeNG son los electrodomésticos ya fabricados (nevera, lavadora). Tailwind es cómo distribuyes los muebles en cada cuarto. Y los tokens son la paleta de pintura: si cambias el color de la pintura en un solo lugar, toda la casa cambia de color a la vez.

2. ¿Qué es un token?

Un token es una variable de diseño: un nombre que guarda un valor (un color, una medida, una sombra). En CSS se escriben con dos guiones al inicio. Todos los nuestros empiezan con --app- para no chocar con los de otras librerías. 

{{ code.colorToken }}

En vez de escribir el color #3b82f6 en 200 sitios, lo guardamos UNA vez en --app-primary-500 y en todos lados usamos ese nombre. ¿La ventaja? Si mañana la marca cambia de azul a verde, tocas un solo archivo y todo se actualiza. Eso es la "fuente única de verdad".

3. Las carpetas de src/styles

Cada carpeta tiene una responsabilidad clara. De arriba hacia abajo, esto es lo que contiene cada una:

Carpeta / archivo ¿Qué es?
abstracts/ Herramientas que no generan CSS por sí solas: la declaración del orden de capas (_layers.scss) y "mixins" responsive (_responsive.scss), que son atajos reutilizables para escribir media queries.
tokens/ El corazón del sistema: todas las variables --app-*. Colores (_colors), tipografía (_typography), espaciado (_spacing), sombras (_elevation) y animación (_motion).
base/ Estilos globales del documento. _reset normaliza diferencias entre navegadores; _base define cosas como el foco accesible, la barra de scroll y la tipografía base de la página.
themes/ _primeng-theme.scss: aquí conectamos nuestros tokens con PrimeNG. Es el puente que hace que los componentes de PrimeNG usen nuestros colores.
typography/ Clases de texto con nombre: .text-heading-xl, .text-body-md, etc. Empaquetan tamaño + grosor + interlineado en un solo nombre semántico.
layout/ Contenedores de página: .container-app (ancho máximo centrado), .container-fluid (ancho completo para tablas), .section (ritmo vertical).
patterns/ Piezas reutilizables de UI: .card, .field (campo de formulario), .status-badge, .empty-state y .skeleton.
utilities/ Animaciones del sistema: solo fadeIn (aparecer) y shimmer (el brillo del skeleton). Enterprise = movimiento contenido.
tailwind.css El punto de entrada de Tailwind. Importa Tailwind y el plugin de PrimeNG, y le dice a Tailwind que use nuestros tokens.
main.scss El "director de orquesta": importa todo lo anterior en el orden correcto. Es lo que se compila al final.
Los archivos que empiezan con guion bajo (_colors.scss) son "parciales": no se compilan solos, solo se incluyen desde main.scss. Es una convención de SCSS.

4. ¿Qué es una capa (@layer)?

Cuando dos reglas de CSS quieren pintar lo mismo de distinto color, el navegador tiene que decidir cuál gana. Tradicionalmente gana "la más específica" o "la última escrita", y eso genera peleas eternas (y el famoso !important).

Las capas (@layer) cambian esa regla: definimos un orden de capas y, sin importar la especificidad, siempre gana la capa que va después. Es como apilar transparencias: la de encima tapa a la de abajo.

Nuestro orden (declarado en abstracts/_layers.scss) es: 

{{ code.layersDecl }}

De menor a mayor prioridad. Lo clave: primeng va antes que sp-theme. Por eso cuando en sp-theme cambiamos un color de PrimeNG, ganamos sin pelear: 

{{ code.layerExample }}
Por eso casi nunca verás !important en el proyecto: el orden de capas ya decide quién gana.

6. La configuración

Hay cuatro archivos que arman todo el engranaje:

  • postcss.config.json

    Activa el plugin de Tailwind v4 para que Angular lo procese al compilar.

  • angular.json → styles

    Define el orden de carga: primero los iconos, luego tailwind.css y al final main.scss. El orden importa.

  • src/styles/tailwind.css

    Importa Tailwind + el plugin de PrimeNG y mapea nuestros tokens a las clases de Tailwind (lo que hace que bg-success use nuestro verde).

  • src/app/app.config.ts

    Configura PrimeNG: el preset Lara (estética enterprise), modo claro fijo, y en qué capa escribe sus estilos. 

{{ code.configSnippet }}
El order de aquí debe ser idéntico al orden de capas de _layers.scss. Si no coinciden, PrimeNG pinta fuera de capa y se rompe toda la cascada.

7. Cómo cambiar un color (paso a paso)

Esta es la pregunta estrella. La respuesta corta: toca un solo archivo. Gracias a los tokens, el cambio se propaga a PrimeNG y a Tailwind a la vez.

1

Abre src/styles/tokens/_colors.scss

Ahí están todos los colores de la marca, agrupados por familia.

2

Cambia el valor del token que quieras

Por ejemplo, pasar la marca de azul a verde: 

{{ code.changeColor }}
3

Guarda. Listo.

No tienes que tocar PrimeNG ni Tailwind. Todo lo que use ese token (botones, links, focus, badges, clases bg-primary-*) cambia automáticamente.

¿Por qué funciona? Por la cadena de conexiones:

_colors.scss            →  --app-primary-500: #16a34a
   │
   ├─►  _primeng-theme.scss   →  --p-primary-500: var(--app-primary-500)
   │      (todos los componentes PrimeNG usan el nuevo color)
   │
   └─►  tailwind.css          →  bg-primary-500 usa var(--app-primary-500)
          (todas las clases de Tailwind usan el nuevo color)
¿Quieres cambiar el borde de los inputs, el radio de los botones o la sombra de los menús? Mismo principio, pero el token vive en _primeng-theme.scss (variables --p-*) o en tokens/ (variables --app-*).

8. Cómo armar una pantalla nueva

Receta rápida para una pantalla típica (como "Gestionar novedades"):

  1. Envuelve todo en un contenedor: .container-app (normal) o .container-fluid (tablas anchas).
  2. Usa clases de Tailwind para el layout: grid, flex, gap-*.
  3. Usa los patrones para las piezas: .card, .field, .status-badge.
  4. Usa clases de texto con nombre para la jerarquía: .text-heading-lg, .text-body-md.
  5. Mete los controles de PrimeNG (p-select, p-table…): ya vienen con nuestros colores.
¿Dudas de cómo se ve algo? Entra a la página /design-system: ahí está el catálogo visual con todos los colores, textos, tarjetas, badges y un formulario de ejemplo.

9. Reglas de oro

Haz

  • Usa siempre tokens --app-*, nunca colores "a mano".
  • Cambia look de PrimeNG en _primeng-theme.scss.
  • Usa Tailwind para layout y espaciado.
  • Reutiliza patrones (.card, .field).

Evita

  • Escribir colores o medidas "a mano" (#fff, 16px).
  • Cambiar PrimeNG con clases de Tailwind.
  • Usar !important (deja que las capas decidan).
  • Duplicar lo que Tailwind o los patrones ya hacen.
